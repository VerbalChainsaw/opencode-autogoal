# v0.4.0 — Goal Chains, Verification, Webhooks, Templates

## Scope

Four additive phases. Each backward-compatible. All new I/O is atomic
(temp + rename) and uses the read-decide-write turn pattern. All new
metadata fields in `sanitizeMetadata` allowlist. No breaking changes.

---

## Phase 1 — Goal Chains

**Concept**: A file-backed step sequencer. `.opencode/.goal-chain.json` stores a
sequence of `GoalChainStep` objects. `.opencode/.goal-state.json` stores the
currently active step. The chain auto-advances on achievement.

### New file

```
src/goal-chain.ts
```

### New type

```typescript
// src/goal-chain.ts
interface GoalChain {
  version: 1;
  id: string;
  steps: GoalChainStep[];
  current: number;
  maxCycles: number;
  onComplete: "stop" | "loop";
  metadata: {
    createdAt: number;
    setBy: "user" | "template";
    sessionId?: string;
  };
}

interface GoalChainStep {
  condition: string;
  command?: string | null;
  maxTurns?: number;      // per-step override, defaults to 20
  maxMinutes?: number;    // per-step override, defaults to 30
}
```

### GoalState metadata additions

```typescript
// src/goal-state.ts, GoalState.metadata:

chainStep?: number;   // which step index (0-based)
chainTotal?: number;  // total steps in the chain
```

### `sanitizeMetadata` additions

```typescript

if (isFiniteNumber(m.chainStep)) out.chainStep = m.chainStep;
```

### New primitives (src/goal-chain.ts)

| Function | Returns | Description |
|---|---|---|
| `readGoalChain(directory)` | `GoalChain \| null` | Parse `.goal-chain.json`, validate shape |
| `writeGoalChainAtomic(dir, chain)` | `void` | temp + rename atomic write |
| `createGoalChain(dir, steps)` | `SetResult` | Write chain + step 0 as active goal |
| `advanceGoalChain(directory)` | `TransitionResult` | Increment current, set next goal |
| `skipGoalChainStep(directory)` | `TransitionResult` | Advance without requiring achievement |
| `resetGoalChain(directory)` | `TransitionResult` | current = 0, restart step 0 |

### `createGoalChain` atomic sequence

```
1. Validate all steps have non-empty conditions
2. writeGoalChainAtomic(dir, chain)
3. Parse step 0, call persistGoal with { condition, command, maxTurns, maxMinutes }
4. Read state back; inject chainId, chainStep=0, chainTotal=N into metadata
5. writeGoalStateAtomic(dir, state)
6. Return { ok: true, state, message: "Step 1/N: <condition>" }
```

### `advanceGoalChain` atomic sequence

```
1. Read chain — return error if not found
2. Read state — return error if state.metadata.chainId !== chain.id (override guard)
3. If current >= steps.length - 1:
   a. onComplete === "stop": mark chain completed, return success
   b. onComplete === "loop" && cycles < maxCycles: reset current to -1, increment cycles
   c. onComplete === "loop" && cycles >= maxCycles: mark completed
4. current += 1
5. writeGoalChainAtomic(dir, chain)
6. Parse steps[current], call persistGoal
7. Read state back; inject chainId, chainStep=current, chainTotal=steps.length
8. writeGoalStateAtomic(dir, state)
9. Return { ok: true, message: "Step N+1/N: <condition>" }
```

### Server.ts integration

Inline in the `evaluate()` achievement path, in the same atomic write turn:

```typescript
if (evaluation.met) {
  f.status = "achieved";
  f.completedAt = Date.now();
  writeGoalStateAtomic(directory, f);

  // Chain advancement — same lock, same atomic boundary
  const chain = readGoalChain(directory);
  if (chain && f.metadata.chainId === chain.id) {
    const adv = advanceGoalChain(directory);
    if (adv.ok) {
      await notify(sessionId, "Chain advanced", adv.message!, "success");
    }
  }

  return { achieved: true, reason: evaluation.reason };
}
```

```typescript
  | { type: "file"; path: string; exists?: boolean; contains?: string }
```

### `validateGoalState` additions

```

- verification.type: must be one of "shell" | "http" | "file" | "marker"
- shell: must have command string
- http: must have url string
- file: must have path string
- marker: no extra fields required
```

### `sanitizeMetadata`

No change — verification is on GoalState, not metadata.

### Server.ts — evaluation dispatcher

```typescript
async function evaluateGoal(state: GoalState, latestTranscript: string): Promise<GoalEvaluation> {
  const v = state.verification;
  if (!v) {
    // Fallback: use deprecated command field if present, otherwise marker
    if (state.command) return evaluateDeterministic(state.command);
    return evaluateByTranscript(latestTranscript);
  }
  switch (v.type) {
    case "shell":  return evaluateDeterministic(v.command);
    case "http":   return evaluateHttp(v, directory);
    case "file":   return evaluateFile(v, directory);
    case "marker": return evaluateByTranscript(latestTranscript);
  }
}
```

### HTTP verification

```
- Uses global fetch() (Node 18+)
- Timeout: verification.timeoutMs ?? 10_000 (via AbortSignal.timeout())
- Checks response.status against expectStatus (default: 200)
- If expectBody set, checks response.text() against regex
- Catches all errors → returns { met: false, reason: "HTTP check failed: ..." }
```

### File verification

```
- Resolves path relative to directory
- Path traversal guard: path.relative(directory, resolved) must not start with ".."
- If exists==false: passes when file does NOT exist
- If contains: readFileSync, test against regex
- Catches ENOENT → returns { met: false } (unless exists==false)
```

## Phase 3 — Webhook Notifications

**Concept**: POST goal state changes to a configurable URL. Fire-and-forget. Localhost
blocked by default.

```typescript
  allowLocal?: boolean;    // opt-in to allow localhost URLs
};
```

### `sanitizeMetadata` additions

```typescript

    Array.isArray((m.webhook as any).on)) {

    url: (m.webhook as any).url,

```

### `validateGoalState` additions

```
- webhook.url: must be http/https string if present
- webhook.on: must be array of valid GoalStatus strings
- webhook.allowLocal: optional boolean
```

### Webhook payload

```json
{
  "goalId": "uuid",
  "chainId": "uuid-or-null",
  "condition": "all tests pass",
  "status": "achieved",
  "previousStatus": "active",
  "turnsEvaluated": 12,
  "lastReason": "npm test exited 0",
  "timestamp": 1718123456789
}
```

### `fireWebhook` function (server.ts)

```typescript
async function fireWebhook(
  state: GoalState,
  previousStatus: GoalStatus | null,
  chainId?: string
): Promise<void> {
  const wh = state.metadata.webhook;
  if (!wh || !wh.on.includes(state.status)) return;

  // Security: block localhost unless opted in
  if (!wh.allowLocal && isLocalUrl(wh.url)) {
    log("warn", "webhook blocked: localhost URL", { url: wh.url });
    return;
  }

  const payload = { goalId: state.id, chainId: chainId ?? null, ... };

  fetch(wh.url, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(payload),
    signal: AbortSignal.timeout(5000),
  }).catch(() => { /* fire-and-forget */ });
}
```

### `isLocalUrl` function

```
Returns true for:
- localhost (any port)
- 127.0.0.0/8
- [::1]
- 0.0.0.0

Does NOT block: 10.x, 172.16.x, 192.168.x, 169.254.x — CI servers use private IPs.
```

### Call sites

`fireWebhook` called after EVERY state transition. Capture payload BEFORE chain
advancement (so the webhook reflects "achieved" not "new step active"):

| Trigger | previousStatus → newStatus | Where |
|---|---|---|
| Goal set | null → active | set_goal / setGoalFields |
| Goal achieved | active → achieved | evaluate() |
| Goal paused | active → paused | pause_goal tool |
| Goal resumed | paused → active | resume_goal tool |
| Goal cleared | active/paused → cleared | clear_goal tool |
| Goal timed out | active → cleared | checkConstraints |
| Goal restarted | any → active | restart_goal tool |
| Goal blocked | active → paused | evaluate() |

### New tool

```
goal_webhook: {
  args: {
    url: tool.schema.string().optional(),
    on: tool.schema.array(tool.schema.string()).optional(),
    allowLocal: tool.schema.boolean().optional(),
```

```
opencode-autogoal webhook https://hooks.slack.com/xxx --on achieved --allow-local
```

## Cross-Cutting Rules

### Data integrity invariants

1. **All writes are atomic**: temp file + rename for both state and
   chain files; no advisory lock file is shared. The achievement
   write and the chain-advance write happen in the same read-decide-
   write turn, with the chain file written before the state file.
2. **All atomic writes**: temp file + rename for both state and chain.
3. **`sanitizeMetadata` completeness**: Every new metadata field added to allowlist.
4. **`validateGoalState` tolerance**: New optional fields don't reject old state files.
5. **No prototype pollution**: Shape validation before any `JSON.parse` result is used.

### Backward compatibility

- All 15 existing tools work identically
- `goal_get_state` JSON shape unchanged for consumers without new features
- `command` field still works (deprecated, not removed)
- Old CLI flags still work
- Existing 514 tests must pass unmodified through all phases

### Security

| Vector | Mitigation |
|---|---|
| Webhook SSRF (localhost) | Blocked by default; `allowLocal` opt-in |
| Webhook SSRF (169.254.x, 10.x) | Documented in SECURITY.md; allowed for CI use |
| File verification path traversal | `path.relative()` check, reject `..` |
| Template import path traversal | Name validated with `/^[A-Za-z0-9_-]+$/` |
| Stdin import hangs on TTY | `process.stdin.isTTY` guard |
| Chain override by manual set_goal | `chainId` mismatch detection |
