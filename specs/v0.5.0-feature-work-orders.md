## Why these five

The strategic goal is "looper agent for other software": OpenGoal as a
goal-loop engine any tool can drive, with OpenCode as one host among many.
F-1/F-2 make the CLI machine-friendly, F-3 gives goals a memory, F-4 gives
every terminal a live dashboard with zero host requirements, F-5 is the
OpenCode Desktop surface. Each builds on shipped v0.4.x infrastructure —
no new dependencies anywhere.

## F-1 — `--json` output mode for the CLI  (effort S, do first)

**Why**: agents and CI parse the CLI today by grepping prose. The structured
envelope already exists; `--json` exposes it. This is the single highest
value-per-line feature in the backlog.

**Behavior**: `opencode-autogoal [--dir <p>] [--json] <command> [args]`
(also accept `--json` before `--dir`; both are leading flags). With
`--json`, stdout is exactly ONE line of JSON and nothing else:

```json
{"ok":true,"kind":"success","exitCode":0,"message":"...","state":{...}|null}
```

- `ok` = `exitCode === 0`; `kind` and `message` verbatim from the envelope;
  `exitCode` from `KIND_TO_EXIT[kind]` (the process still exits with it).
- `state`: ONLY for `view`/`status` results — the sanitized state from
  `readGoalStateSafe(directory).state` (single-sourced sanitization; do
  NOT re-implement). All other commands: omit the field entirely.
- `agentExtras` is never emitted (agent-only scaffolding).
- Errors must honor the flag too: unknown command / parseArgs throw →
  `{"ok":false,"kind":"usage","exitCode":1,"message":"<the error text>"}`
  on stdout, nothing on stderr, exit 1. `help` with `--json` prints the
  normal help text (help is for humans; document this).

**Files**: `src/cli.ts` (extend `ParsedArgs` with `json: boolean`; flag
loop generalizing the `--dir` parse), README (one subsection + example
under the CLI docs), CLI header comment.

**Tests first** (`test/cli-json.test.mjs` + e2e additions):
- unit: parseArgs variants (`--json status`, `--dir X --json status`,
  `--json --dir X status`) → `json: true`, correct action.
- e2e: `--json status` in a temp dir with no goal → parses as JSON, kind
  `no-goal`, exitCode 2, process exit 2, `state` absent.
- e2e: set a goal, `--json status` → `ok:true`, `state.condition` matches,
  `state` field present and validator-shaped.
- e2e: corrupt state file planted → kind `corrupt-state`, exitCode 4.
- e2e: `--json zzz` (unknown) → single-line JSON on stdout, exit 1,
  stderr empty.
- e2e: stdout is exactly one line (`out.trim().split("\n").length === 1`).

## F-2 — `doctor` command  (effort S)

**Why**: "is my setup healthy?" currently requires knowing four file
paths and the quarantine convention. One command, CI-friendly.

**Behavior**: `opencode-autogoal [--dir] [--json] doctor` prints a check
table and exits 0 (healthy) / 1 (any FAIL):

| Check | OK | WARN | FAIL |
|---|---|---|---|
| goal state | valid or absent | — | corrupt (note: this read QUARANTINES the file — doctor says so and names the artifact) |
| chain file | valid or absent | — | corrupt (same) |
| handoff file | valid or absent | — | corrupt (same) |
| quarantined artifacts | none | N found (list newest 3, suggest deletion) | — |
| node version | >= 20 | — | < 20 |
| package version | always OK, prints version from its own package.json | | |

Implementation: a pure `runDoctor(directory): { checks: Array<{name,
status: "ok"|"warn"|"fail", detail}>; healthy: boolean }` in `src/cli.ts`
(exported for tests), using `readGoalStateResult` / `readHandoffResult` /
`readGoalChainResult` / `listCorruptArtifacts`. `doctor` is handled in
`main()` BEFORE the dispatcher (it is not a goal action; do not add it to
`CLI_TO_DISPATCHER` or the dispatcher). With `--json`: emit the runDoctor
result object as one line. Exit 0/1 only (doctor never exits 2-4).

**Tests first**: clean dir → healthy, exit 0; corrupt state planted →
fail + artifact named + file actually quarantined; artifacts present →
warn; `--json doctor` parses and `healthy === false` ⇒ exit 1.

## F-3 — Goal archive + `stats`  (effort M)

**Why**: terminal goals vanish today (overwritten by the next `set`).
An append-only archive gives users a record, gives `stats` a data source,
and gives the Desktop panel a future History tab — all from one JSONL file.

**Storage**: `.opencode/goal-archive.jsonl`, one line per terminal event:
`{"archivedAt": <ms>, "outcome": "achieved"|"cleared"|"replaced", "state": <GoalState>}`.
Gitignore it (same block as the state files). Caps: before append, if file
size > 1 MB, atomically rewrite keeping only the newest 200 lines (tmp +
rename, reuse the random-suffix tmp pattern). Reads cap at 2 MB and skip
unparseable lines silently (count them, surface as a one-line note).

**New module** `src/goal-archive.ts` (add to tsconfig.build.json include +
package.json files[] is NOT needed — dist ships whole): exports
`appendGoalArchive(directory, state: GoalState, outcome): void` (best-effort:
every failure swallowed — archiving must NEVER break a goal transition) and
`readGoalArchive(directory, limit = 10): { entries: ArchiveEntry[];
skippedCorrupt: number }` (newest first). Import direction: goal-archive.ts
imports ONLY `type GoalState` from goal-state.js (type-only import — erased
at build, so the goal-state → goal-archive value-import is not a cycle).

**Chokepoint wiring** (all three, each one line + comment):
1. achieved — server.ts ~387, after `writeGoalStateAtomic`: `appendGoalArchive(directory, f, "achieved")`.
2. cleared — `transitionGoal`'s clear branch after its successful write.
3. replaced — `persistGoal`: when `replaced !== null` AND
   `validateGoalState(existing)` (raw-reader content must pass the
   validator before being archived; invalid → skip, do not archive garbage).

**CLI/dispatcher**: new actions `archive` (list newest 10:
`#N <outcome> "<condition 60-char>" <ISO date> (<turns> turns)`) and
`stats` (`{ total, achieved, cleared, replaced, avgTurnsToAchieve }`,
human one-liner per stat; `--json` composes via F-1 automatically since
both run through the dispatcher envelope: kind `success`, or `no-goal`
with message "No archived goals yet." when empty). Add to KNOWN_ACTIONS,
CLI_TO_DISPATCHER, HELP, README.

**Tests first**: append/read round-trip; outcome recorded per chokepoint
(set → clear → archive has "cleared"; set → set → "replaced"); corrupt
line skipped + counted; 1 MB trim keeps newest 200; `stats` math
(avgTurnsToAchieve over achieved only); archive failure injected (read-only
dir) does not break `clear`; dispatcher kinds; e2e `--json stats`.

## F-4 — `watch` — live terminal dashboard  (effort M, independent of F-3)

**Why**: the sidebar/TUI need OpenCode. `watch` turns ANY terminal into a
live goal readout — tmux pane, second terminal, SSH session. Zero deps:
plain ANSI, built entirely on `createGoalWatcher` + `presentGoalState`.

**Behavior**: `opencode-autogoal [--dir] watch [--interval <ms>]`:
- Long-running; handled in `main()` before the dispatcher (like doctor).
  Returns only on exit; SIGINT → `watcher.dispose()` → exit 0.
- Each update: clear screen + home (`\x1b[2J\x1b[H`), render one frame.
- Frame content (pure function `renderWatchFrame(result: GoalStateResult,
  handoffPresent: boolean, width: number, now: number): string` — exported,
  unit-testable, NO ANSI inside except the bar color; the clear codes live
  in the render loop): header `<icon> <statusLabel> — opencode-autogoal vX`,
  condition (wrap at width), `presentGoalState` bar
  (`█`/`░`, progressPct), turnsLabel · timeLabel · tokensLabel, lastReason,
  steeringCount + chainStep when present, corrupt → warning block naming
  `listCorruptArtifacts(dir)[0]`, absent state → "No goal set." +
  set-command hint. Footer: `ctrl-c to exit · polling every <n>s`.
- `--interval` clamps to [250, 60000] (parsePositiveInt; out of range →
  usage error exit 1).
- **Non-TTY** (`!process.stdout.isTTY`): print ONE frame, no ANSI clear,
  exit 0 immediately (CI/pipe safe). This is also the e2e test path.

**Tests first**: `renderWatchFrame` unit tests per state (active/paused/
corrupt/absent — feed synthetic GoalStateResult, assert key substrings and
that output contains NO `\x1b` except the bar); interval clamp; e2e:
spawn `watch` with stdout piped (non-TTY) in temp dir → exactly one frame,
exit 0, contains "No goal set."
